# 번역 에이전트 지침서

이 저장소는 Degrees of Lewdity 한국어 번역판에 영문 0.5.13.8을 병합한 것입니다. 영문이 문장을 고친 자리와 새로 추가한 콘텐츠가 영어로 남아 있습니다. 당신의 임무는 **지정된 파일 안의 영어 산문을 한국어로 바꾸는 것**입니다. 그 밖의 파일은 건드리지 않고, 커밋하지 않습니다.

## 1. 절대 바꾸지 않는 것

번역은 **글자만** 바꿉니다. 아래는 코드이며 한 글자도 바꾸면 안 됩니다.

| 보존 | 예 |
|---|---|
| 매크로 이름·인자 구조·순서 | `<<if $rng gte 21 or $novaginal is 1>>`, `<<set $speechSpank to 1>>`, `<<link [[Next\|Forest Cabin]]>>`의 `[[…\|Forest Cabin]]` 대상 |
| 변수 | `$money`, `_npcId`, `V.settings.x`, `C.npc.Avery.rage` |
| 값으로 쓰이는 문자열 | `<<set $x to "m">>`, `either("m","f")`, `$worn.lower.name is "naked"`, CSS 클래스(`class="gold"`), 패시지 이름, `id="…"`, `data-…="…"` |
| HTML 태그와 속성 | `<span class="gold">`, `<br>`, `<<link>>` 안의 `[[대상]]` |
| 줄 구조 | 줄을 합치거나 나누지 않습니다. 매크로가 있는 줄은 매크로 위치를 유지합니다. |

바꿀 수 있는 것: 산문, 대사, `<<link "다음">>`·`<<button "예">>`·`<<print "…">>`처럼 **화면에 찍히는** 문자열, `[[다음|Forest Cabin]]`의 라벨 부분, `title="…"` 툴팁, `` `…` `` 템플릿 안의 글자(안의 매크로·변수는 그대로).

대명사·명사 위젯(`<<he>>`, `<<He>>`, `<<his>>`, `<<person1>>`, `<<girl>>`, `<<bitch>>` 등 인자 없는 것)은 한국어 문장에 맞게 **생략하거나 자리를 옮겨도 됩니다**. 그 밖의 매크로는 생략·이동 금지입니다. 허용 목록은 `translation/text-macros.txt`에 있습니다.

## 2. 옛 번역 활용

파일마다 `translation/pending/<파일 경로>.json`에 기록이 있습니다. 항목의 뜻:

- `old_en`: 병합 전 영문, `old_kr`: 그 자리의 옛 한국어 번역, `new_en`: 지금 파일에 들어 있는 새 영문(이것을 번역합니다), `context`: 바로 앞 줄.
- `kind`가 `conflict`면 옛 번역이 밀려난 자리입니다. 영문이 조금만 바뀌었다면 `old_kr`을 바탕으로 바뀐 만큼만 손봅니다. 영문이 구조를 바꿨다면(옛 한글 여러 줄이 매크로 한 줄과 짝지어진 경우 등) `old_kr`은 용어·말투 참고로만 쓰고 새 영문을 새로 번역합니다.
- `kind`가 `merged-new-text`면 완전히 새 영문입니다. 같은 파일에 살아 있는 한글 줄의 어조를 따릅니다.

작업은 **파일 전체**를 대상으로 합니다. 기록에 없는 영어 산문이 보이면 그것도 번역합니다. 기록에 있어도 이미 한글이면 손대지 않습니다.

## 3. 말투와 표기

- 플레이어는 "당신". 서술은 현재형 평서문("…한다"). 대사는 인물의 기존 어조를 따릅니다(같은 파일이나 `game/base-combat/speech/`의 살아 있는 한글 대사 참고).
- NPC 이름 표기는 `game/base-system/named-npcs.twee`와 `game/kr_js/kr_dict.js`를 따릅니다(에이버리, 휘트니, 로빈, 카일라, 시드니, 에덴, 알렉스, 베일리, 그윌란, 윈터, 모건, 조던, 베일리 등).
- 장소·아이템 이름은 저장소 안에서 `grep`으로 기존 표기를 찾아 맞춥니다. 처음 나오는 이름은 자연스러운 음역을 택하고 보고에 적습니다.
- 영어 단어·매크로·변수 뒤에 조사가 올 때는 반드시 **조사 마커**를 씁니다. 게임이 앞 글자의 받침을 보고 자동으로 고릅니다.

| 마커 | 뜻 | 예 |
|---|---|---|
| 【은는】 | 은/는 | `<<he>>【은는】 웃는다` |
| 【이가】 | 이/가 | `<<person1>>【이가】 다가온다` |
| 【을를】 | 을/를 | `$name【을를】 부른다` |
| 【와과】 | 와/과 | `<<him>>【와과】 함께` |
| 【으로로】 | 으로/로 | `<<bottom>>【으로로】` |
| 【아야】 | 아/야(호격) | `<<bitch>>【아야】!` |
| 【이나나】 | 이나/나 | |
| 【이】 | 이(서술격 '이다' 앞) | `<<girl>>【이】다` |
| 【이었였】 | 이었/였 | |

이 아홉 가지만 씁니다. 【의】【에게】【도】 같은 것은 마커가 아니라 그냥 글자로 씁니다("…의", "…에게").

## 4. 번역하는 문자열과 아닌 문자열

| 번역함 | 번역 안 함 |
|---|---|
| `<<link "Next">>` → `<<link "다음">>` | `<<link [[Next\|Shop]]>>`의 `Shop` |
| `[[Leave\|Street]]` → `[[나간다\|Street]]` | `<<goto "Street">>` |
| `<span class="gold">Money:</span>` → `돈:` | `class="gold"` |
| `<<= $x ? \`"Fuck!" <<he>> hisses\` : \`…\`>>` 안의 글자 | 그 안의 `<<he>>`, `$x` |
| `title="…"`·`tooltip="…"`, `<input type="button" value="Save">`의 value | `id`, `data-*`, `style`, `<option value>`, `type="file"`의 value |
| | `@data-tip="_x + ' skin tone'"`처럼 속성 안에서 코드와 이어 붙는 영어: 붙는 산문도 영어로 둔다 |
| `displayName: "Percentage of men"` (JS) | `name: "naked"`, `type: "m"`, 키 이름 |

JS 파일(`.js`)은 사용자에게 보이는 문자열(`displayName`, `description`, `name_lower`, 메시지)만 번역합니다. 의상 파일의 `name:`은 게임 로직의 키라서 번역하지 않습니다. 음식 항목에는 옛 번역처럼 `counter: "개"`(단위: 개·병·송이·잔 등) 줄을 **추가**할 수 있습니다. 그 밖의 속성 추가·코드 변경은 금지입니다.

## 5. 끝낼 때

1. 담당 파일마다 영어 산문이 남지 않았는지 훑습니다. 번역할 수 없는 자리(의미를 알 수 없는 조각, 고유명사)는 영어로 두고 보고에 적습니다.
2. 검사기를 돌립니다. 전부 `ok`여야 합니다. `FAIL`이면 메시지의 토큰·줄 번호를 보고 고칩니다(대개 매크로나 링크 대상을 건드린 것입니다).

```bash
python3 tools/check_translation.py <파일1> <파일2> ...
```

3. 보고 형식(짧게):
   - 파일별: `ok`/`FAIL`, 검사기가 찍은 "english lines left" 수, 영어를 남긴 자리와 이유.
   - 처음 정한 표기(이름·용어)와 애매했던 선택.
   - 코드처럼 보여 건드리지 않은 문자열 중 사실은 번역해야 할지 모르는 것.
