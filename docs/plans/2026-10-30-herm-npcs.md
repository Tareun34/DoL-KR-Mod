# Herm NPCs 패치 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한글판 DoL 0.5.12.13 HTML에 "NPC가 자지와 보지를 모두 가질 수 있는 비율" 설정을 넣는 두 번째 패치 스크립트 `patch/herm.py`를 만들고, 원격 세이브 패치와 순서대로 적용하는 `build.sh`를 추가한다.

**Architecture:** `herm.py`는 `patch.py`와 같은 "앵커를 정확히 한 번 찾아 치환" 방식이다. 차이는 치환 대상이 트위 패시지(`<tw-passagedata name="...">` 안의 HTML 이스케이프된 본문)라는 점으로, 치환 규칙은 사람이 읽는 원문으로 적고 매칭 직전에 이스케이프한다. JS 한 곳(`settingsObjects`)은 이스케이프 없이 원문에서 찾는다. 모든 규칙은 `(패시지 이름 또는 None, 규칙 이름, 원문, 치환문)` 튜플의 표 하나로 선언한다.

**Tech Stack:** Python 3.9+ 표준 라이브러리만, `unittest`. 트위/SugarCube 2 문법.

**Spec:** `docs/specs/2026-10-30-herm-npcs-design.md`

## Global Constraints

- 외부 의존성 없음. Python 3.9에서 돌아야 한다 (`str.removeprefix` 등 3.9 이상 기능은 가능, 3.10 문법인 `match`는 금지).
- 입력 파일은 `encoding="utf-8", newline=""`로 읽고 쓴다 (`patch.py`와 동일). 줄바꿈과 탭을 그대로 보존한다.
- 앵커 불일치 시 `missing anchor: <이름>` / `ambiguous anchor: <이름> (<n>)`, 이미 패치된 입력은 `already patched`. 모두 stderr, 종료 코드 1, 아무 파일도 쓰지 않는다.
- 패시지 본문 이스케이프 테이블은 정확히 `& → &amp;`, `< → &lt;`, `> → &gt;`, `" → &quot;`, `' → &#39;` 이 순서(`&`가 먼저).
- 새 설정 키 이름은 `femaleNPCHermChance`, `maleNPCHermChance`. 기본값 0. 반응 억제 기준값은 양성 20, 겉모습 불일치 50.
- 치환문의 들여쓰기는 원문과 같은 탭 깊이를 유지한다.
- 테스트 실행 명령: `cd dol-remote-save && python3 -m unittest discover -s patch/test -p 'test_*.py'`.
- 커밋은 `dol-remote-save/` 저장소에서, 기존 관례(`feat(patch): ...`, `docs: ...`)를 따른다.

## Review Focus

1. 패시지 본문에 `&#39;`가 들어 있는 경우: 앵커에 작은따옴표가 없으면 무관하지만, `esc()`가 `'`를 `&#x27;`(html.escape 기본)로 바꾸면 실제 파일과 안 맞는다. → Task 1 `test_esc_matches_game_entity_table`.
2. 같은 앵커 문자열이 다른 패시지에도 있는 경우(`random(0, 99) gte $settings.maleNPCVaginaChance`는 네임드와 지속 NPC 둘 다에 있음): 패시지 범위를 벗어나 전체 파일에서 세면 ambiguous가 난다. → Task 2 `test_named_and_persistent_share_anchor_text`.
3. 이름이 접두사 관계인 패시지(`Widgets NPCs` 와 `Widgets NPC Generation`): 이름 매칭이 부분 일치면 잘못된 패시지를 고친다. → Task 1 `test_passage_lookup_is_exact_name`.
4. 패치 후 재적용: 삽입형 규칙은 앵커가 남아 두 번째 실행이 성공하면 설정 슬라이더가 두 개씩 생긴다. → Task 3 `test_patching_twice_fails`.
5. 원격 세이브 패치와의 체인: herm.py 결과에 patch.py가 그대로 적용돼야 한다. → Task 5 `test_chain_with_remote_save_patch`.

**Files:**
- Create: `patch/herm.py`
- Test: `patch/test/test_herm.py`

**Interfaces:**
- Consumes: `patch.PatchError`, `patch._find_once(text, needle, name) -> int`
- Produces:

  - `patch_html(html: str) -> str`.
  - 이후 Task들은 `REPLACEMENTS`에 튜플을 추가할 뿐, 함수 시그니처는 바뀌지 않는다.

def esc(t):
    for a, b in (("&", "&amp;"), ("<", "&lt;"), (">", "&gt;"), ('"', "&quot;"), ("'", "&#39;")):
        t = t.replace(a, b)
    return t

def passage(name, body):
    return '<tw-passagedata pid="1" name="%s" tags="widget">%s</tw-passagedata>' % (name, esc(body))

def build_html(js=None, **bodies):

class EscapeAndLookupTests(unittest.TestCase):
    def test_esc_matches_game_entity_table(self):
        self.assertEqual(herm.esc('<<if a & b>> "x" \'y\''), "&lt;&lt;if a &amp; b&gt;&gt; &quot;x&quot; &#39;y&#39;")

    def test_passage_lookup_is_exact_name(self):
        html = passage("Widgets NPCs", "A") + passage("Widgets NPC Generation", "B")
        s, e = herm.passage_span(html, "Widgets NPCs")
        self.assertEqual(html[s:e], "A")

    def test_missing_passage_names_it(self):
        with self.assertRaises(patch.PatchError) as cm:
            herm.passage_span("<html></html>", "Widgets NPCs")
        self.assertIn("passage/Widgets NPCs", str(cm.exception))

    def test_duplicate_passage_is_ambiguous(self):
        html = passage("Widgets NPCs", "A") * 2
        with self.assertRaises(patch.PatchError) as cm:
            herm.passage_span(html, "Widgets NPCs")
        self.assertIn("ambiguous", str(cm.exception))


class RandomNpcGenerationTests(unittest.TestCase):
    def test_debug_gate_replaced_by_herm_chance(self):
        out = herm.patch_html(build_html())
        self.assertNotIn("debugEnableHerms", out)
        self.assertIn(esc('<<elseif $rng lte $settings.femaleNPCPenisChance + ($settings.femaleNPCHermChance || 0)>>'), out)
        self.assertIn(esc('<<elseif $rng lte $settings.maleNPCVaginaChance + ($settings.maleNPCHermChance || 0)>>'), out)

- [ ] **Step 4: `patch/herm.py` 구현**

모듈 docstring은 `patch.py`와 같은 형식(첫 줄 한 문장, Usage 줄). 상수: `DEFAULT_INPUT`(`patch.py`와 동일 경로), `DEFAULT_OUT_DIR = os.path.join(REPO, "build")`, `ALREADY_PATCHED_MARK = "femaleNPCHermChance"`.

`esc(text)`: 테이블을 튜플로 두고 순서대로 `replace`.

`passage_span(html, name)`: 정규식 `<tw-passagedata\b[^>]*\bname="NAME"[^>]*>` (`NAME`은 `re.escape(esc(name))`)로 모든 매치를 찾아 개수 검사 후, 매치 끝부터 다음 `</tw-passagedata>`까지를 본문으로 반환.

`REPLACEMENTS`의 첫 두 항목(규칙 이름 `npc-generation-m`, `npc-generation-f`, 패시지 `Widgets NPC Generation`). 원문은 위 `NPC_GEN`의 남성 if-체인 11줄(`\t\t\t<<if $rng lte $settings.maleNPCVaginaChance and $debugEnableHerms is 1>>` 부터 `\t\t\t<</if>>` 까지)과 여성 if-체인 11줄. 치환문(남성):

```
			<<if $rng lte $settings.maleNPCVaginaChance>>
				<<set $NPCList[_n].vagina to "clothed">>
				<<set $NPCList[_n].gender to "f">>
			<<elseif $rng lte $settings.maleNPCVaginaChance + ($settings.maleNPCHermChance || 0)>>
				<<set $NPCList[_n].penis to "clothed">>
				<<set $NPCList[_n].vagina to "clothed">>
				<<set $NPCList[_n].gender to "h">>
			<<else>>
				<<set $NPCList[_n].penis to "clothed">>
				<<set $NPCList[_n].gender to "m">>
			<</if>>
```

여성은 대칭: 첫 분기 `femaleNPCPenisChance` → penis, gender "m"; 둘째 `femaleNPCPenisChance + (femaleNPCHermChance || 0)` → vagina+penis, gender "h"; else vagina, gender "f".

`patch_html(html)`:
1. `ALREADY_PATCHED_MARK in html`이면 `PatchError("already patched")`.
2. 규칙을 순서대로 적용. 패시지 규칙은 `passage_span`으로 본문을 잘라 `_find_once(body, esc(old), name)` 후 `esc(new)`로 바꾸고 다시 이어 붙인다. `passage=None` 규칙은 `_find_once(html, old, name)` 후 그대로 치환.
3. 치환된 문자열 반환. 파일 쓰기는 `main`에서만.

    def setUp(self):
