# 영문 0.5.13.8 추종 1단계(병합) 설계

작성일: 2026-11-10. 대상 저장소: `Tareun34/DoL-KR-Mod`. 선행 문서: `2026-11-09-dol-kr-mod-design.md`.

## 1. 의도와 배경

이 저장소의 게임 소스는 한국어 번역판 0.5.12.13이다. 영문 원본은 0.5.13.8까지 나왔고(2026-11-10 기준 `master` == 태그 `0.5.13.8`, 커밋 `fa81d94d1`), 그 사이에 "Dark History" 대형 업데이트가 들어 있다. 번역 저장소의 원 관리자는 유지보수를 종료했으므로 가져올 한글 0.5.13은 없다. 우리가 직접 올린다.

작업은 두 단계로 나눈다.

- **1단계(이 문서)**: 영문 0.5.13.8의 코드·이미지·구조를 받아들여, 빌드되고 플레이되는 **한영 혼재** 0.5.13.8 한글판을 만든다. 번역이 사라진 자리와 새 영문이 들어온 자리를 빠짐없이 기록해 2단계가 쓸 작업 목록을 남긴다.
- **2단계(별도 설계)**: 기록을 따라 재번역·신규 번역을 파일 단위로 채운다.

**목표**

- `game/`, `img/`, `modules/`, `types/`와 관련 설정 파일이 영문 0.5.13.8과 같은 구조·코드가 된다. 영문이 추가한 콘텐츠는 영어로라도 전부 들어 있다.

- 2단계 작업 목록이 저장소에 남는다: 번역이 밀려난 자리(충돌), 새 영문이 들어온 자리(깨끗이 병합된 추가분), 새 파일. 각 항목에 옛 한글·옛 영문·새 영문이 함께 기록된다.
- 병합 도구는 재사용 가능하다. 다음 영문 버전(0.5.13.9 등)이 나오면 같은 도구로 같은 절차를 밟는다.

**비목표**

- 번역(재번역·신규 번역) 자체. 2단계 설계에서 다룬다.

**금지(이렇게 되면 실패)**

- 영문이 손대지 않은 자리의 한글 번역이 사라지는 것.
- 영문 0.5.13.8에 있는 패시지가 우리 빌드에 없거나, 우리 빌드에만 있는 패시지가 생기는 것(한글판이 추가한 위젯 패시지는 예외로 명시 목록을 둔다).

- 원본 변형에 Herm 설정이 노출되는 것(선행 설계의 금지 조항 유지).
- 기존 세이브(`server/saves/`) 유실. 수동 확인(4절 8) 전에 `server/saves/` 전체를 저장소 밖 `/home/chan/game/backup/saves-<날짜>/`에 복사해 둔다.

## 3. 병합 방식

### 3.1 세 입력

| 이름 | 위치 | 내용 |
|---|---|---|
| BASE | `/home/chan/game/degrees-of-lewdity-0.5.12.13` (worktree, 커밋 `0354ffeb8`) | 영문 0.5.12.13 |
| NEW | `/home/chan/game/degrees-of-lewdity-0.5.13.8` (worktree, 태그 `0.5.13.8`) — 작업 시 새로 만든다 | 영문 0.5.13.8 |
| OURS | 이 저장소 작업 트리 | 한글 0.5.12.13 + Herm 이식 |

도구는 세 경로를 인자로 받는다. 경로를 하드코딩하지 않는다.

### 3.2 범위

병합 대상(NEW 기준으로 맞춘다):

- `game/` 전체. 단 `game/kr_js/`는 OURS 그대로 둔다.
- `img/` 전체: OURS가 BASE와 동일하므로 NEW로 덮고 BASE에만 있던 파일은 지운다(이름 변경 19건 포함).
- `modules/`, `types/`: OURS가 BASE와 동일하므로 NEW로 덮는다.
- 단일 파일: `version`, `DoL Changelog.txt`, `package.json`, `package-lock.json`, `.eslintrc.cjs`, `deprecated.twee-config.yml`, `t3lt.twee-config.yml`, `devTools/apkbuilder/config.xml`, `DolSettingsExport.json`→`DolSettingsExport.js`(삭제+추가).

건드리지 않는 것: `README.md`, `.gitignore`, `build.sh`, `devTools/tweego/`(한글판 스토리 포맷과 원격 저장 포맷), `features/`, `server/`, `tools/`, `docs/`, `.vscode`, `.cspell*`.

### 3.3 파일별 규칙(`game/`, `modules/`, `types/`의 텍스트 파일)

1. BASE에 없고 NEW에 있음 → 복사. 기록: `new-file`.
2. BASE에 있고 NEW에 없음 → 삭제. OURS가 BASE와 달랐다면(번역이 있었다면) 기록: `deleted-translated`.
3. 둘 다 있고 OURS == BASE → NEW 복사. 기록 없음(번역이 없던 파일).
4. 둘 다 있고 BASE == NEW → OURS 유지. 기록 없음.
5. 그 외 → `git merge-file`과 같은 3-way 병합(OURS, BASE, NEW).
   - 충돌 없는 덩어리는 그대로 적용한다. 그중 NEW가 줄을 추가·변경한 덩어리는 기록: `merged-new-text`(새 영문이 번역 없이 들어온 자리).
   - 충돌 덩어리는 **NEW 쪽을 채택**한다. 기록: `conflict`(옛 한글이 밀려난 자리).

### 3.4 기록 형식

`translation/pending/` 아래에 원본 경로를 그대로 따른 JSON 파일 하나씩(예: `translation/pending/game/base-combat/man-combat.twee.json`). 각 파일은 항목 배열이고, 항목은 다음을 가진다.

- `kind`: `conflict` | `merged-new-text` | `new-file` | `deleted-translated`
- `old_en`: BASE 쪽 줄들(문자열 배열, 없으면 빈 배열)
- `old_kr`: OURS 쪽 줄들(충돌·삭제에서만; 그 외 빈 배열)
- `new_en`: NEW 쪽 줄들(결과 파일에 실제로 들어간 텍스트; 삭제에서는 빈 배열)
- `context`: 결과 파일에서 해당 자리 바로 앞 줄 1개(위치 힌트, 비어 있을 수 있음)

줄 번호는 기록하지 않는다. 2단계에서 파일이 바뀌면 줄 번호는 어긋나지만 `new_en` 텍스트는 번역될 때까지 그대로 남아 있기 때문이다. **항목은 `new_en`이 결과 파일에 더 이상 그대로 없으면 완료된 것으로 본다.** `new-file`은 `new_en`에 파일 전체를 넣지 않고 빈 배열로 두며, 완료 판정은 2단계 설계가 정한다(1단계에서는 항상 미완료).

`translation/STATUS.md`는 생성물이다. 디렉터리별로 항목 수(종류별)와 완료 수를 표로 적고, 머리에 생성 시각과 대상 영문 태그를 적는다. 커밋한다.

### 3.5 Herm 이식 복구

3.3의 규칙대로면 Herm 이식 변경(OURS 쪽 변경)은 영문이 같은 자리를 고친 곳에서 NEW에 밀려난다. 자동 병합이 끝난 뒤 **별도 단계**로 Herm 규칙 15개를 다시 점검하고 빠진 것을 수동으로 재적용한다. 기준은 `2026-10-30-herm-npcs-design.md`의 규칙 목록과 `tools/test/test_herm_gating.py`의 5개 가드다. 재적용 결과는 "Herm 변형과 원본 변형의 빌드 차이가 Herm 관련 패시지에만 있고 스크립트 차이가 `features.js`와 `save.js`의 Herm 항목뿐"으로 확인한다. 기대 패시지 목록은 0.5.12.13 때(`Widgets Settings`, `variablesVersionUpdate`, `presets` + 스크립트 12줄)를 출발점으로 하되 영문 구조 변화에 따라 달라질 수 있으므로 작업자가 확인하고 README와 커밋 메시지에 새 목록을 남긴다.

Herm 이식이 끝날 때까지는 **원본 변형이 Herm 설정을 노출하지 않는지**를 가장 먼저 본다. `save.js`의 `randomize` 게이팅, `importSettingsData`의 키 삭제, `presets.twee`의 미리보기 게이팅이 살아 있어야 한다.

### 3.6 한글 전용 식별자 점검

OURS 쪽 코드 변경 중 번역이 아닌 로직(한글 전용 위젯 정의, `window.KR.*` 호출, 조사 마커 등)이 충돌로 밀려나면, 다른 곳에서 그 이름을 쓰는 코드가 깨진다. tweego는 이것을 잡지 못한다.

이름 규칙(`Kr` 접미사, `kr_js/` 위치)으로는 부족하다. 검토에서 확인한 바 `window.KR.*` 정의 4개가 `kr_js/` 밖(`04-Pregnancy/child-generator.js`, `sexShopMenu.js`)에 있고, 접미사 없는 한글 전용 로직(`setup.hcItemNames`, `setup.normalizeColourKey`, `window.hcTranslateName`, `window.resolveFoodstuffKey`, `homePillDisplayName` 등)도 있다. 그래서 기준을 **"OURS에는 있고 BASE에는 없는 정의 전부"**로 잡는다(작성자 결정).

- 병합 **전에** OURS와 BASE에서 정의 이름을 수집한다: 위젯(`<<widget "이름">>`), `setup.이름 =`, `window.이름 =`(점 하나 더 내려간 `window.KR.이름 =` 포함), 최상위 `function 이름(`. OURS에만 있는 이름이 "한글판 전용 정의"다.
- 병합 **후에** 결과 트리에서 그 이름이 참조되는데(위젯은 `<<이름`, 나머지는 이름 그대로) 정의가 없으면 실패 항목이다.
- 보고서에 실패 항목을 파일·이름으로 나열한다. 0건이어야 1단계가 끝난다. 발견되면 해당 정의를 `translation/pending`의 `old_kr`에서 되살려 수동으로 넣는다(동작 복구가 목적이므로 그 덩어리의 영문 본문은 그대로 둔다).

이 점검은 이름 단위라서, 이름은 남았지만 동작이 바뀐 경우는 잡지 못한다(7절).

### 3.7 빌드와 버전

- `version` 파일이 NEW를 따라 `0.5.13.8`이 되므로 `build.sh`의 출력 이름은 자동으로 `DoL-KR 0.5.13.8 *.html`이 된다. `build.sh`는 고치지 않는다.
- 0.5.12.13 HTML 네 개는 `dist/`에 **보관용**으로 남긴다(같은 이름이 아니므로 `build.sh`가 덮지 않는다). 플레이는 새 버전으로 바로 전환한다(사용자 결정, 2026-11-10). 영문이 이미지 19개의 경로를 바꿨고 `img/`는 하나뿐이므로 옛 빌드는 홍조·스토킹 아이콘 등 일부 이미지가 깨진 채 남는다. 또 0.5.13.8에서 저장한 세이브는 0.5.12.13에서 열리지 않을 수 있다. 둘 다 README에 적는다.
- 영문 비교 빌드: NEW worktree에서 `compile.sh`(또는 같은 tweego 호출)로 영문 0.5.13.8 HTML을 저장소 밖(`/home/chan/game/baseline/en-0.5.13.8.html`)에 만든다. 커밋하지 않는다.

6. 사용자 수동 확인(4절 8) 후 `main` 병합·push.

## 6. 작업자에게 맡기는 것

- 3-way 병합 구현 방식(`git merge-file` 호출 또는 `difflib` 기반 자체 구현). 결과가 3.3 규칙과 같으면 된다. 단 `git merge-file`을 쓰면 덩어리 경계와 기록이 그 출력에 맞춰지므로, 기록 추출이 가능한 쪽을 고른다.
- `merged-new-text`에서 "NEW가 줄을 추가·변경한 덩어리"의 경계 정의(BASE→NEW diff의 덩어리 단위를 권장).
- STATUS.md의 표 모양, 보고서 출력 형식, 테스트용 가짜 트리의 구성.
- Herm 재적용의 구체적 코드(규칙은 선행 문서가 정의).
- 브랜치 이름과 커밋 분할. 단 자동 병합 결과는 반드시 단독 커밋이어야 한다(되돌리기 쉽게).

## 7. 검토에서 확인된 전제(2026-11-10, 빌더 체크)

- 스토리 포맷, tweego, `compile.sh`, `devTools/head.html`은 두 태그 사이에 변화가 없다. 원격 저장 포맷은 그대로 쓴다.
- 게임 코드가 `idb.*`를 직접 부르는 곳이 없어 원격 저장 동작에 영향이 없다.
- 패시지 이름은 한글판과 영문 0.5.12.13이 완전히 같다. 4절 4의 허용 목록은 비어 있을 가능성이 크다.
- Herm 규칙 15개의 앵커(`$debugEnableHerms` 분기, `random(0, 99)` 성별 결정, `femaleNPCPenisChance` 슬라이더, `importSettingsData`, `presetConfirm`)는 0.5.13.8에도 그대로 있다.

## 8. 알려진 위험

- 큰 충돌 덩어리(최대 1,999줄)는 파일 하나의 번역이 통째로 밀려난다. 기록에는 남으므로 2단계에서 복구 가능하지만, 1단계 결과물에서 그 파일은 전부 영어다.
- 영문이 JS 쪽 구조를 바꾼 곳(`save.js` +1991/-1022 등)은 한글 전용 로직이 함께 밀려날 수 있다. 3.6 점검이 이름 단위로만 잡으므로, 이름은 같지만 동작이 바뀐 경우는 잡지 못한다. 4절 8의 수동 확인과 2단계 번역 과정에서 발견되는 대로 고친다.
- 옛 0.5.12.13 빌드는 보관용이라 이미지 일부가 깨진다(3.7). 되돌려야 할 때는 `git`에서 0.5.12.13 시점의 `img/`를 꺼내 서버에 따로 얹어야 한다.
- Herm 재적용은 사람이 하는 작업이다. 가드 5개와 빌드 비교로 확인하지만, 선행 문서의 규칙 15개 중 가드가 없는 규칙(생성 비율 계산 등)은 코드 리뷰로 확인한다.
